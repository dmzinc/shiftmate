# ShiftMate mobile implementation plan

## Agreed product decisions
- Platforms: Android and iOS.
- Runtime: Capacitor 8.
- Experience: native-feeling application, not an external-site wrapper.
- Offline: full offline rota viewing and shift/note editing, with sync when online.
- Notifications: local shift reminders and remote push notifications.
- Backend: existing Supabase project; web app remains supported.

## Repository baseline and branch changes
The current production app is a single-page HTML/CSS/JavaScript application (index.html + app.js) using Supabase JS and SheetJS from CDN URLs.

This feature branch adds:
- Capacitor 8 core, CLI, Android/iOS platform and native plugin dependencies.
- capacitor.config.ts with app ID com.shiftmate.app.
- An isolated www/ mobile bundle generated by npm run build:mobile.
- Supabase JS and SheetJS bundled locally for mobile boot (no CDN dependency for these core libraries).
- Native plugin dependencies for app lifecycle, device, filesystem, haptics, keyboard, network, local notifications, push notifications, preferences, splash screen and status bar.
- A mobile QA checklist.

## Stage 0 — local toolchain
1. Install Node.js 22 LTS or newer and npm.
2. Android: install Android Studio and Android SDK.
3. iOS: use macOS with Xcode and CocoaPods. iOS native projects cannot be built on Windows.
4. From repository root:
   npm install
   npm run build:mobile
   npx cap add android
   On macOS: npx cap add ios
   npm run cap:sync
5. Open Android Studio with npm run cap:open:android; open Xcode with npm run cap:open:ios.
6. Do not commit signing keys, provisioning profiles, keystores, service-account JSON, APNs keys or FCM service credentials.

## Stage 1 — mobile web bundle and responsive UX
The first mobile bundle pipeline is implemented. Before release:
- Run it on Windows and macOS and inspect generated www/ output.
- Test login, registration, email verification, password recovery and deep links.
- Test Excel/CSV file selection using Android document providers and iOS Files/iCloud Drive.
- Test large workbook parsing, modals, keyboard resizing, accessibility and small-screen layouts.
- Pin and audit dependencies; commit a lockfile generated by npm.
- Consider moving the existing single-file app to a maintainable module structure after the mobile baseline is stable.

## Stage 2 — native application integration
Integrate and test:
- App lifecycle and deep links using @capacitor/app.
- Native file picker / Files integration for .xlsx, .xls and .csv imports. Verify Android document providers and iCloud Drive.
- Network status messaging and retry controls.
- Status bar, splash screen, keyboard resizing and haptics.
- Platform-specific icons, launch screens, permissions and privacy disclosures.

Email confirmation and password-reset links must use verified HTTPS app links / Universal Links and a custom URL scheme fallback. Configure matching Supabase Auth redirect allow-lists and Android App Links / iOS Universal Links. Never redirect production users to localhost.

## Stage 3 — offline-first data architecture (required for full offline)
A service-worker cache alone is not offline data support. Implement an explicit local database and sync engine before claiming full offline support.

Recommended design:
- SQLite database on device with encryption at rest; select and validate a Capacitor SQLite plugin for Capacitor 8 before adding it.
- Tables: rotations, shifts, shift_notes, sync_queue, sync_metadata.
- Scope every local row by authenticated Supabase user ID. Clear local database and queued data on sign-out/account switch.
- Read screens from SQLite first; refresh from Supabase when online.
- Mutations write locally and enqueue an operation atomically.
- Queue entries carry UUID, entity, entity ID, operation, payload, user ID, created_at, retry count and idempotency key.
- Process queue on reconnect and app resume with bounded exponential backoff.
- Add server-side updated_at/version fields and soft-delete/tombstone handling before enabling offline edits.
- Conflict policy: never silently overwrite. Use optimistic concurrency/version checks and a conflict-resolution UI. Notes can use append-only versions; shift/rotation edits need field-aware conflict handling.
- Show pending/synced/conflict state and last-sync time.
- Do not cache private rota or note content in shared browser caches.

Acceptance criteria:
1. Previously synced rotations and shifts open in airplane mode.
2. Users can create/edit/delete shifts and notes offline.
3. Closing/restarting the app does not lose queued changes.
4. Reconnecting syncs operations idempotently.
5. Concurrent edits create visible conflicts, not silent data loss.
6. Signing out clears local user data and pending operations.

## Stage 4 — notifications
Local reminders:
- Schedule/cancel reminders on-device from the user's rota.
- Store reminder preferences and timezone per user.
- Reconcile reminders after rota changes, app updates and timezone changes.
- Request permission contextually, not on first launch.

Remote push:
- Add a device registration table with owner-only RLS and unique device token.
- Register FCM on Android and APNs (or APNs via FCM) on iOS.
- Send pushes only from trusted server/Edge Function code using server-side secrets.
- Never ship service-role credentials or FCM/APNs secrets in the client.
- Revoke device registrations on logout and handle token rotation.
- Keep shift details out of lock-screen notifications by default; allow opt-in previews.

## Stage 5 — security, privacy and compliance
- Confirm RLS for every user-owned table and test cross-account access.
- Store only minimum required data locally and encrypt it at rest.
- Use platform secure storage for refresh-token/key material where supported.
- Biometric unlock is an additional local gate, not a replacement for Supabase authentication.
- Provide privacy policy, data deletion/export process, permission rationale and store privacy declarations.
- Avoid collecting patient-identifiable information in notes.

## Stage 6 — release and QA gates
Android:
- Build signed AAB, test physical devices, validate file import, notifications, deep links, offline sync, rotation changes and upgrade path.
- Use Google Play internal testing before production.

iOS:
- Build/archive with Xcode on macOS, test physical iPhones, validate Files/iCloud import, APNs, Universal Links, offline sync and background behaviour.
- Use TestFlight before App Store submission.

Both platforms:
- Authentication and password recovery.
- Email verification deep links.
- Known and unseen rota workbook formats.
- Offline CRUD, sync and conflict tests.
- Local reminders and remote push.
- RLS/security regression and account isolation.
- Accessibility, small-screen layout, performance and crash-free smoke tests.
